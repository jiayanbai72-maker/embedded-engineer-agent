# 通用嵌入式知识库第一版

当前先建立与具体芯片无关的工程知识，并导入可检索的知识卡片。暂停桌宠构建与硬件确认，不影响该案例原始资料。

## 分类

1. requirements：需求、约束、验收。
2. architecture：模块、接口、状态机、资源预算。
3. hardware：电气兼容性、供电、接口检查。
4. concurrency：中断、任务、共享资源与同步。
5. build：交叉编译、依赖、环境与产物。
6. debugging：证据、假设、定位、修复、复测。
7. testing：单元、集成、仿真和实机验证。
8. delivery：复现、交付、变更与未验证项。

## 资料分层

- general：自主编写的跨平台工程方法。不能作为器件电气参数或规范符合性证明。
- ecosystem：跨芯片但限于某生态的官方参考摘要，例如 FreeRTOS、CMSIS、Zephyr、CMake。只有条件匹配时可用于建议。
- device：具体芯片、模块和开发板，后续按需求导入。
- case：项目案例与经验，独立维护，不自动提升为通用规则。

首批内容为自主工程方法卡片和官方资料短摘要，不是完整手册镜像，也不是已完成自动网页/PDF 抽取。
官方摘要保留 URL、章节、查阅日期和版本范围。动态文档不能直接指导任意版本 API；生成代码前需核对项目版本。

## 当前工具

`tools/knowledge.py import knowledge/seed_cards.json --output knowledge/index.json`

`tools/knowledge.py search knowledge/index.json --query 需求 --scope general`

默认仅检索 general；加入生态资料必须显式选择 ecosystem 或 all。
当前为本地关键词检索，没有向量检索、语言模型或自动方案执行。返回结果是候选证据，不是最终设计。

## 导入契约

每张卡片记录 id、标题、分类、层级、适用条件、来源类别、来源地址、章节、版本、查阅日期与正文。
工具检查字段、分类、重复 ID、来源类别及官方引用，并对正文生成哈希。
导入生成结果采用临时文件替换，错误时不发布部分索引。导入成功不等于内容已被工程验证。

## 下一阶段

让需求 Agent 输出目标功能、预算、时序、功耗、接口和未知项，随后检索相关卡片，生成带依据的候选方案。
选定生态和器件后再读取匹配版本的官方资料。任何具体芯片参数仍需专属证据。

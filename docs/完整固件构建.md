# 完整固件构建模块

已增加演练板卡配置、启动代码、内存布局和映像校验，并接入服务与决策控制器。
本版生成真实工具链产物，但板卡配置是示范配置，不是经过验证的实体开发板配置。

## 构建链

C源码 → ARMCC目标文件 → ARMASM启动目标文件 → ARMLINK链接AXF/Map → FROMELF导出BIN/HEX → 产物检查 → 打包。
编译器位置由本机 EMBEDDED_AGENT_ARMCC 指定；汇编、链接、转换工具来自同一安装目录。
不接受用户提供任意命令或可执行路径。

## 演练配置

名称 generic-cortex-m3-build-demo，CPU Cortex-M3。
FLASH 起始0、64KiB；RAM 起始0x20000000、20KiB；栈1KiB。
这些是演练参数，不是通过特定芯片手册核验的选型结论，不允许用于直接烧录实际板卡。
仅 mode=demonstration_only 可以进入当前完整构建适配器。
校验地址范围、容量、对齐、重叠及栈大小。

启动文件包含核心向量表、初始栈、Reset_Handler 与默认异常处理，调用 __main 完成运行库初始化。
尚未包含实际芯片时钟、外部中断表、外设初始化、系统配置和GPIO绑定。
主程序使用合成输入，计数变量是演练可观察状态，不是实际毫秒时基。

## 服务接口

分析决策声明 actions=[firmware_build, export_documents]。
用户确认需求和选方案后，提交 firmware_implementation：revision、files、profile、rationale。
执行 firmware_build：revision。失败保留 firmware_build_failed，允许受预算约束的修复；成功允许交付。
控制器支持同名动作，真实日志作为后续判断输入。

## 产物与检查

- AXF：检查ELF文件标识。
- BIN：检查容量、初始栈指针、复位Thumb入口及地址范围。
- HEX：检查记录长度、校验和、结束记录、数据地址、向量表和BIN一致性。
- Map：保存链接布局，供人工或后续工具检查。
- 构建记录：源码哈希、编译器版本、工具命令、退出状态、日志、产物大小与哈希。

编译和链接成功只说明构建完成。hardware 始终为 not_run；不承诺实际板卡启动、按键响应、功耗或实时性。
交付包含源码、生成的startup.s/layout.sct、board-profile.json、固件文件及构建记录。
可以通过 examples/run_firmware_build.py 重跑演练。

# 实物接口与自动发现

设备发现是 Agent 工具能力，不依赖聊天助手手动执行系统命令。换模型后仍可调用相同的工具契约。当前没有合适的开发板，不开展板卡连接、烧录或真实日志验收；零件电路板不能默认具有电脑接口。

## 已有能力

- `discover_hardware {}`：模型可调用的只读工具，枚举串口与 Windows USB 描述。不会打开端口。工作台也通过 `GET /hardware/devices` 调用同一实现。
- USB VID/PID、驱动名称、序列号和位置属于检测依据；不把转串口芯片认作主控，不把摄像头的 DFU 接口认作开发板。目前没有完整开发板识别数据库，未知的主控和板卡型号保持空值。
- 工作台“实物连接”提供自动检测、用户选择串口和一次授权。绑定接口为 `POST /projects/{id}/hardware_bind {revision,port,fingerprint,baudrate,confirmed:true,board_label?}`。只有用户操作能绑定；模型不能自行更换设备或波特率。
- `hardware_capture {seconds?}`：获得授权后，模型可按1至10秒、最多64KB接收原始串口数据。固定8N1，不发送协议命令，关闭软件和硬件流控，打开前将DTR/RTS设置为False。依赖驱动的打开行为仍可能导致某些板卡复位，因此用户授权时有明确说明。
- 采集前重新比对端口元数据指纹；设备断开或变化则要求重新选择。指纹不是芯片或固件身份认证，也无法保证区分所有相同转接器。
- 保存时间、配置、原始字节、SHA-256和UTF-8预览；编码异常不丢弃原始数据。原始字节可随交付包导出。

捕获到日志只记为 captured，没有收到数据记为 no_data；端口失败记为 failed。三者都不意味着硬件功能通过。项目 verification.hardware 保持 not_run，绑定与采集不会替用户确认需求或改变其他工程阶段。新增硬件记录会使旧交付包失效，需要重新生成。

## 依赖与边界

可选依赖为 `pyserial==3.5`，在本项目 runtime/dependencies 中安装供本地服务使用；标准安装可选 project 的 hardware extra。Windows USB元数据枚举使用固定只读系统查询，没有模型提供的命令或参数；失败时明确报告权限或枚举问题。

串口读取依据：[pySerial API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html)、[端口枚举说明](https://pyserial.readthedocs.io/en/latest/tools.html)。

当前不支持自动烧录、驱动执行器、CanMV REPL交互、协议指令发送或实机验收。开发板资料与识别规则仍可按需求补充，不宣称覆盖所有型号。未来云端版本通过本地执行端复用这些接口，不能把云端机器自身的USB清单当成用户电脑的设备。

## 验证结果

测试覆盖枚举不打开端口、不臆测主控、用户授权和设备变化校验、模拟字节流采集、禁止发送、原始字节保留和持久化不误报实机通过。模拟串口不代表真实开发板验证。本机新代码只读枚举结果记录于 runtime/hardware-discovery.json：检测未发现串口，USB枚举成功，没有打开任何设备。

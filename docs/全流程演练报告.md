# 按键事件记录器全流程演练报告

已完成分析者辅助、真实 HTTP 服务和主机行为原型的开发调试交付闭环。没有调用真实模型 API，没有执行 MCU 烧录或硬件验证。

## 需求与判断

由分析者选择演练需求：稳定 20ms 后确认按键状态，一次按下产生一个事件，长按不重复，释放后重新触发，短暂抖动不计数，倒退时间输入被拒绝。
选择事件驱动状态机，原因是当前单一输入、处理路径短，不需要任务调度。RTOS 候选方案保留给后续复杂并发情形。
接口通过外部注入采样时间，使边界和抖动可以重复测试；实际 GPIO、电平、采样频率和时钟回绕后续由硬件适配验证。

## 实际执行

1. HTTP 创建项目，提交本次分析的需求、方案和执行动作。
2. 按全流程演练授权确认范围，选择状态机方案；没有替用户确认真实硬件项目。
3. 提交源码及测试，真实执行 Python py_compile。
4. 故意注入严格大于比较的边界错误，真实执行测试并记录失败。
5. 停止并重新启动 HTTP 服务，从持久化项目恢复 test_failed 状态。
6. 判断原因：稳定时长恰好 20ms 时，严格大于条件不成立。
7. 仅将条件改为大于等于；原测试保持不变。
8. 重新执行编译检查与测试，四项行为测试通过。
9. 服务生成 ZIP 并通过 HTTP 下载，保存哈希及验收记录。

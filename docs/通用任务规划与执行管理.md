# 通用任务规划与执行管理

在工作台“分析者入口”选择或创建运行，下方“通用任务计划”载入示例，编辑后保存。提交下一步决策时选择关联任务，再使用原有执行按钮。系统没有连接真实模型：目标理解、任务拆解和调整仍由外部分析者完成；系统负责依赖校验、执行与反馈记录。示例不会根据自然语言自动生成完整工程计划。

## 计划接口

`POST /runs/{run_id}/plan`，请求携带当前运行 `revision` 和 `plan`。`GET /runs/{run_id}` 返回 `task_progress`。

```json
{
  "revision": 0,
  "plan": {
    "goal": "检索供电相关资料，形成可追溯的来源",
    "rationale": "先获取原文，再审核参数，避免使用猜测值选型",
    "source": "local_analyst",
    "tasks": [
      {
        "id": "research",
        "title": "检索官方资料",
        "action": "search_documents",
        "depends_on": [],
        "completion": {"status": "executed", "tool_result.status": "passed"}
      }
    ]
  }
}
```

有计划的运行，决策还须携带 `task_id`；动作须与当前可执行任务一致。参数仍放在原有 `arguments` 中，计划不会自行构造参数。完成条件是对真实控制器回执的字段逐项比较；构建可要求 `tool_result.status: passed`，验证可要求 `project_status: ready_delivery`。检索执行成功不等于参数已核实，空结果需要分析者检查回执并调整检索。不要把“完成检索”定义成“通过选型”。

## 反馈与恢复

- 缺失依赖或当前工程阶段不支持时，显示阻塞原因。
- 执行结果不符合完成条件时标为待分析，不能直接解锁下游。
- 调整已有计划须在 `response_to` 中引用真实决策回执编号，并填写调整依据 `rationale`。旧版完整保存，新版从零验证，避免沿用失效完成结论。
- 控制器保存计划、任务关联及回执；重启后重新计算进度，沿用现有幂等与不确定中断保护。
- 外部操作改变项目版本时，计划显示过期；刷新运行后将旧计划归档，分析者需要重新规划。新版编号不会复用旧版编号。
- `user_input` 表示等待用户补充，不允许分析者将其伪装成执行成功。用户补充工程需求后刷新运行并重新规划。
- 用户确认、选型接受及接受估算风险仍使用用户操作入口，不作为分析者可执行任务。规划不能增加烧录、采购或任意命令执行权限。

本层提供可检查的计划与反馈闭环，不代表已经实现自主推理模型、自动参数审核、实物调试或无人值守交付。计划完成比例也不等于整个硬件项目完成比例。

# 工作台与分析者入口

设置 PYTHONPATH 为 src 后运行 `python -m embedded_agent.server --port 8765`，浏览器打开 http://127.0.0.1:8765/。
界面与API来自同一本地服务，不需要前端构建或额外依赖。

Windows 可运行根目录的 `启动工作台.ps1`，它将服务作为隐藏的独立后台进程启动，检查健康状态并保存日志。
如果 PowerShell 禁止运行脚本，直接双击根目录的 `start-workbench.cmd`。此入口调用 Python 启动器，自动打开浏览器，不改变 PowerShell 执行策略。
重复运行会检测已运行的服务；系统重启后需重新运行启动脚本。若启动失败，查看 runtime/server.stderr.log。

## 项目操作

创建项目：用语言描述目标。项目保存后进入等待分析。
补充需求：填写条件或修正，提交会使下游结果失效。
确认需求：分析完成且没有阻塞问题后可确认。
选择方案：需求确认后，比较架构、取舍、条件和风险再选择。
交付下载：对应执行成功后开放。验证范围分别显示主机、MCU模块、固件构建和实机状态。
左侧列表显示本机已有项目；浏览器记住最后打开的项目，服务重启后可继续读取。

## 分析者入口

切换到分析者入口，复制项目上下文，提供给本次对话或其他可信分析者。
分析者输出符合契约的JSON；粘贴或导入后点击校验并提交。
分析来源和判断依据保留在项目档案中。分析契约参考 examples/analyst-door-monitor.json，不自动套用示例到任意新项目。

创建决策运行后，复制运行上下文，包含允许动作、工具结果、剩余预算和项目状态。
填写动作、参数JSON、依据、预期与分析来源，提交决策。服务先校验，点击执行后才调用实际工具。
每次观察执行结果，再决定下一步。不能由分析者接口代替用户确认需求或方案。
用户修改或确认导致项目版本变化时，点击同步项目变更，再读取新上下文。
源码提交的files和profile等参数仍属于分析者的工程数据，普通用户不需要填写。

## 边界

当前角色切换是协作视图，不是身份认证与权限隔离；仅用于可信本地操作。
未连接独立模型时不会自动生成分析；有分析者提交结果后服务继续。
不接受跨来源浏览器请求，支持本页同源请求。动态内容使用文本节点显示，不解析用户HTML。
执行器可运行源码，因此公共部署前仍需安全隔离、认证和作业队列。

## 本轮验证

31项后端与构建测试通过。浏览器中已验证创建项目、粘贴分析并提交、确认需求、选择方案、新建运行、提交决策、执行、交付下载入口和刷新恢复。
采用独立界面验收项目，不代表真实硬件需求已获用户确认。文档交付不会将构建、选型或实机阶段自动标为已完成。

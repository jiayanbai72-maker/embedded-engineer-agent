# 通用需求分析入口

该入口将任意嵌入式项目描述转成需求草稿，再检索通用知识并比较条件式方案。
不默认指定芯片，不读取桌宠资料作为所有用户的固定需求，不执行硬件操作。

## 使用

设置 PYTHONPATH 为项目的 src 目录，并在本机设置以下环境变量：

- EMBEDDED_AGENT_ENDPOINT：完整的 HTTPS Chat Completions 接口地址。
- EMBEDDED_AGENT_MODEL：服务实际支持的模型名。
- EMBEDDED_AGENT_API_KEY：本机密钥，不要写入项目资料或聊天。

程序不自动加载 .env；.env.example 只提供字段说明。未配置模型仍可创建项目，但分析状态为 unsupported。
兼容服务需要支持 messages、response_format=json_object、choices 与 finish_reason；不能保证每个供应商兼容。
配置模型后，需求描述与选出的通用知识卡片将发送到指定服务。单次完整分析通常调用模型两次，不自动循环重试。

```text
python -m embedded_agent.cli analyze --description "设计一个电池供电的门窗提醒设备，手机可以查看状态"
python -m embedded_agent.cli show PROJECT_ID
python -m embedded_agent.cli supplement PROJECT_ID --message "希望续航三个月，使用家里的网络"
```

## 输出

项目 artifacts.requirements 包含：

- requirements：功能、编号、验收方法与 explicit/proposed 来源。
- constraints：约束和值，以及 explicit/proposed 来源。
- assumptions：假设。
- questions：未知项、编号与 blocking 标记。
- search_queries：模型提取的检索关键词。
- evidence：实际检索到的卡片与出处。
- comparison：候选模块架构、覆盖需求、取舍、条件、风险、证据与芯片能力要求。

所有结果均保持 draft/conditional，等待用户补充或确认。用户补充后重做分析，旧草稿留在项目事件中。
当前未实现确认后自动进入设计阶段；用户补充不等于用户确认全部需求。

方案比较引用必须来自实际检索结果；芯片 verified 标记必须有 device 层资料。
当前入口只检索 general，因此具体芯片不能被标为 verified，最终芯片选型仍为 not_finalized。
后续选型阶段将导入匹配型号与版本的资料，并验证电气、资源、接口和预算。
引用存在性校验不代表引用能支持所有结论，仍需后续证据审核。

## 当前验证范围

测试使用明确标注的模型与网络替身，验证两次调用、知识检索、状态保存、补充、错误和证据边界。
尚未配置真实服务时，不能声称已验证真实模型的需求理解质量、延迟或效果。
API 结构依据官方文档核对：
https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create
JSON 模式只保证 JSON 形式，不替代本项目的字段和引用校验。

# 工作台验证与修复闭环

更新：2026-10-18。范围：已有工程草案的离线编译、原始 mock 测试和已关联扩展边界测试。

## 用户入口

项目操作中的“软件验证与修复”显示原测试、扩展测试和 MCU 编译的实际状态。

1. 如已有本项目的边界审计用例，可点击“关联已有 N 类扩展测试”。关联操作不调用模型，旧验证及旧交付会失效，测试内容和原测试哈希会冻结。
2. 选择与已定芯片一致的内核，点击“运行全部测试（不调用模型）”。此步骤真实调用本地工具链。
3. 失败时点击“让智能体修复并复测（计入预算）”。模型只提交一个生产文件的最小补丁，控制器校验后保存；不允许修改原测试或扩展测试。
4. 复测通过后，程序可继续打包并结束本轮，不为这些确定步骤额外请求模型。软件通过不等于完整固件链接、电气审查或实物验收通过。

“自动推进”仍保留运行步数、修复次数、重复失败、模型费用不确定等暂停规则，不因本次接入取消保护或清零账本。

## 已接入的机制

- `test_suites.py` 从本项目已有审计目录加载用例，校验名称、目录范围、项目 ID 和内容哈希；不得从页面提交任意文件路径。
- 用例保存到项目的 `draft_test_suite`，模型没有关联或替换测试集的控制器动作权限。
- `draft_verify` 先运行原测试与目标编译，通过后运行隔离组合测试，结果统一保存到 `draft_verification`。
- 扩展失败会作为当前修复错误返回，即使原测试通过，项目也不进入 `draft_verified`。
- `execute` 同时核对当前源码哈希与冻结测试集哈希、通过状态；下载包包含冻结用例、原报告及扩展报告。
- `ModelDecider` 在草案验证失败且允许 `draft_patch` 时转入精简定向修复；其他阶段仍走普通决策。
- 确定性调度复用已记录 CPU 执行测试、打包与结束；不盲目猜测 CPU，也不增加模型调用。
- 页面保留简要当前动作与等待秒数，详细历史折叠展示，停止时不再次复制整段错误。

## 验证与限制

新增回归用例覆盖：篡改扩展测试拒绝导入、其他项目/路径拒绝、扩展失败禁止交付、旧报告无法绕过测试集、原测试被改动禁止验证，以及一次模型替身修复后不再调用模型即可复测、打包与结束。

实际项目通过工作台同一 HTTP 接口完成八类用例关联、ARMCC 和 MSVC 编译、原测试及扩展测试、交付包生成，费用账本前后核对不变。替身流程测试验证编排机制，不构成对线上模型能力的认证。

未关联扩展测试集的其他项目仍只运行其原测试，界面明确显示“未关联”；系统不会把当前机器人用例自动套给其他项目。新增或变更冻结测试仍需人工审核，当前入口拒绝不同内容的替换。尚未覆盖的行为和硬件条件继续单独验证。

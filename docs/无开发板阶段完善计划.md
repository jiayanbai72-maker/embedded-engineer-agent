# 无开发板阶段完善计划

当前范围：先完善通用智能体软件流程，不以没有开发板为理由反复中断，也不把模拟验证当实机验收。

六组离线检查：需求和契约；资料、引用与假设；方案、图纸和源码草案；诊断、修复与复验；调度恢复和进度；交付边界与费用保护。运行tools/run_offline_curriculum.py生成runtime/offline-training/latest.json与latest.md，工作台“能力与交付检查”可查看。只运行本地测试，不调用模型、不枚举或连接实物。

报告绑定源代码指纹；代码变化后历史通过不自动当成当前版本通过。框架回归与模型能力评估分开显示。单个合成模型案例通过不能算通用排错能力；当前机器人仍有独立的失败状态。

软件验收要求：能保留冻结需求和证据；生成实际文件；编译与测试绑定当前源码；原测试不得被删改；失败给出变量值、调用来源；修复后重验；连续无进展或预算不足停止；交付包含真实结果和未完成项。

后续模型实训应增加独立留出案例：未声明符号与接口同步、定时阶段/回绕、无效参数与缺少HAL、越界/空输入、回调扇出及回归退化。每次记录模型调用数、费用、通过率及人工介入；先小规模预算评估，不无限自动训练。

无需开发板仍可继续：依据原厂资料确定引脚和接口、完善电路草案、编写板级驱动、完整固件编译与链接；真正缺资料或工具时说明具体缺口，不能笼统归因于没有开发板。

需要实物的项目留后：烧录、实机动作与语音、电气测量、峰值电流与48小时续航。采购预算需真实报价。软件回归不能替代这些证据。

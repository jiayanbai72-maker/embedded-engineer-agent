# 资料检索、页码引用与选型证据

当前版本使用本地 SQLite FTS5 全文检索，无模型、嵌入服务或云端依赖。中英文按词与中文双字切分，部分工程中文词提供英文映射；这是关键词检索，不是任意自然语言语义理解。输入具体型号与简短术语效果更好。没有命中时应换关键词或补资料，不能生成不存在的引用。

## 工作台操作

打开 http://127.0.0.1:8765/ ，选择项目后点击“资料与证据”。

1. 检索型号与术语，例如 `TMP117 recommended operating conditions`。
2. 点击“读取此页”，打开原始资料核对表格、具体型号、版本和条件。PDF 显示从 1 开始的物理页码，可能与手册印刷页码不同；网页和文本没有页码。
3. 登记具体参数、数值、单位、条件、引用原文、审核者及说明，并明确确认。记录保存到 `runtime/knowledge/parameters/`，获得 `PAR-…` 编号。引用至少8字符且必须出现在对应页面；服务不自动证明引用在语义上支持数值。
4. 在检查 JSON 的 `parameter_bindings` 中填写参数编号、型号与条件。字段含义、单位、数值、型号、条件与来源版本均需一致。不自动换算单位。
5. 提交检查；缺证据时报告 `needs_evidence`，不冒充通过。通过后可“确认选型并继续”，系统再次核对证据再进入后续阶段。

参数审核是可信本地分析者的明确判断，不是整个文档已审核，也不是经过身份认证的电子签名。没有自主模型；本工具让分析者或未来模型执行检索、读取和检查，并保留结果。模型输出的 `reviewed:true` 不能代替参数登记。

## 输入字段和单位

| 检查 | 必须绑定的硬件或报价事实 | 单位 |
|---|---|---|
| voltage | output_min_v、output_max_v、input_min_v、input_max_v | V |
| resource | available，登记参数名为 `资源名称.available`，如 `PWM.available` | count |
| energy | battery_v、capacity_mah、usable_fraction、idle_mw、active_mw | V、mAh、fraction、mW、mW |
| budget | shipping_cny、parts.0.unit_price_cny 等每项报价 | CNY |

其余参数（预算上限、需求资源数量、目标时长、动作累计时长、储备比例、采购数量）是明确提交的需求或设计条件，不被当作官方器件事实。能耗模型按提交的整机闲置/活动功耗计算，不从单个芯片休眠电流推断整机功耗。预算仍需真实报价；当前官方资料库没有采购价格凭证导入流程，不能凭手册判定100元预算满足。

绑定格式示例（编号须换成当前真实审核记录）：

```json
{
  "checks": [{
    "id": "PWM-CAPACITY",
    "kind": "resource",
    "inputs": {"resource": "PWM", "available": 4, "required": 3},
    "parameter_bindings": {
      "available": {"parameter_id": "PAR-实际审核编号", "model": "实际器件型号", "conditions": "与审核记录完全一致的条件"}
    }
  }]
}
```

只核对提交的检查范围。电压区间检查不是逻辑 VIH/VIL、驱动电流、上电时序、纹波和瞬态验证；资源计数检查不保证引脚复用可同时实现。参数含义和适用场景仍需分析者审核。

## 分析者与 Agent 工具

- `documents.search` / 决策动作 `search_documents`：`{query, limit?, document_id?}`。
- `documents.page` / `read_document_page`：`{document_id, page}`；网页传 null。
- `parameters.read` / `read_parameter`：`{id}`。

这些读取动作写入决策运行的观察记录，不修改项目版本，也不自动确认用户需求。参数审核不作为自动决策动作开放。

HTTP 接口：

- `GET /knowledge/status`：索引状态与目录是否变化。
- `POST /knowledge/search`：同上检索参数，返回页面、片段、来源、哈希与原始文件入口。
- `POST /knowledge/page`：返回完整提取页面。
- `GET /knowledge/documents/{document_id}/file`：按索引编号读取原始文件，不能传入任意路径。
- `POST /knowledge/parameters`：明确的本地参数审核，字段对应工作台表单。
- `GET /knowledge/parameters`：有效记录与失效状态。
- `POST /projects/{id}/selection_check`：`{revision, proposal}`。
- `POST /projects/{id}/continue_selection`：`{revision, confirmed:true}`。

## 索引与失效

索引位于 `runtime/knowledge/pages.sqlite3`，从 `knowledge/official/catalog.json` 的合格文本建立。源 PDF、提取文本和页码索引均保存哈希；检索引用、参数读取和检查时核对来源版本。文件变化需重建并重新审核参数；不会静默让旧值适用于新版本。

新增资料并更新统一目录后，运行 `tools/build_document_index.py`。索引原子替换，运行中的服务下次读取可直接使用。已保存参数与索引重启后可继续使用。

交付的 `selection-check.json` 包含计算结果及实际解析的参数记录、原文、页码、哈希和审核条件，方便追溯；它不是整机实测证书。

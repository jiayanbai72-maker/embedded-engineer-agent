# Keil 工程构建适配器

## 使用

在工作台“项目操作”页下方“现有 Keil 工程”输入 `.uvprojx` 或 XML `.uvproj` 的完整路径。单 Target 可留空目标名称，多 Target 需填写。确认可信工程和构建副本授权后，点击“导入副本并构建”。工作台展示选定 Target、器件信息、错误文件与行号以及日志。无需开发板；不执行下载、烧录、调试器运行。

默认使用 `C:\Keil_v5\UV4\UV4.exe`；可通过本机环境变量 `EMBEDDED_AGENT_UVISION` 指定其他绝对路径，重启服务生效。适配器调用 `UV4 -r <project> -t <target> -o <unique-log>`。0表示无警告，1表示仅警告；本适配器还必须看到零错误的构建摘要，不能仅根据返回码判成功。

命令与退出码依据：[Keil 官方命令行文档](https://www.keil.com/support/man/docs/uv4/uv4_commandline.asp)。支持日志中 ARMCC `file(line): error...` 和 ArmClang `file:line:column: error...` 位置格式；链接器没有源码位置的错误保留在原始日志中，不编造行号。

## 决策闭环

导入是用户操作 `POST /projects/{id}/keil_import {revision,file,target?,confirmed:true}`，不开放给模型自行导入任意路径。导入范围仅当前任务工作空间；将工程目录复制到 runtime/keil，模型只修改副本。

现有决策控制器新增动作：

- `keil_build {}`：构建并返回退出码、日志、源码哈希、diagnostics。
- `read_keil_source {file}`：读取导入清单内文件，返回原内容、编码、SHA-256。file 使用清单中的相对路径；diagnostics.source_file 提供能映射到清单的路径。
- `keil_edit {changes:[{file,sha256,content}],rationale}`：核对读取时的哈希，保留原内容及修改后哈希，然后重新进入待构建状态。

模型读取实际错误后先读源码，再提交有依据的修改并再次构建。源码修复计入已有修复预算；改完不等于成功，必须重新构建通过。工程构建结果进入运行回执，自动循环可继续决定修复或暂停。当前真实模型尚未连接，不能宣称模型已能自主修复未知报错。

超时标为状态不确定，不自动重试。用户核实没有遗留编译进程后重新导入。编译器、设备包、许可证、第三方库缺失时必须报告缺失，不能靠删除功能或测试实现表面通过。没有下载或安装依赖的自动权限。

## 首版范围

支持 XML 工程的一个显式 Target；暂不支持工作空间批量构建、工程目录外的源码/头文件路径、绝对外部依赖、路径宏、启用的构建前后自定义命令。导入目录须自包含，源码最多200KB/文件，工程副本最多100MB。路径、链接与副本哈希检查防止误改原文件，但 Keil 仍是可信本地工程执行，不是对恶意源码或编译选项的安全沙箱。

源码支持 UTF-8、带 BOM 的 UTF-8 和 GB18030，写回保留编码。当前最多每次改10个已有源码文件，不提供模型任意创建、删除文件或修改工程配置能力。项目配置改变需重新导入。包含外部目录的真实项目可先由用户整理成自包含工程；系统不会悄悄改路径或工程参数。

构建通过后可使用原交付入口，交付包含副本工程、输出文件、构建日志与源码修改历史。实机状态保持 not_run，构建通过不代表电气、时序、功能或硬件验收通过。

## 本机验证

对现有实例资料中的 STM32F103C8 工程创建独立副本，Target 1，使用本机 µVision/ARMCC V5.06 update 4：

1. 原始副本构建通过，0错误、0警告。
2. 明确在副本 User/main.c 加入 #error，真实构建失败；解析到第61行、#35错误。
3. 移除该明确注入的错误后真实构建再次通过；核对原始文件哈希未变化。

这是实际 Keil 编译与日志解析验证，注入与移除操作由 Codex 明确编写，不是未知错误的模型自主修复。运行记录在 runtime/keil-verification-report.json，失败和复测完整日志分别在 keil-verification-failed.json、keil-verification-fixed.json。

另外增加隔离单元测试，验证编码读取、哈希冲突拒绝、越界与自定义命令拒绝，以及控制器“失败→读源码→修改→重新构建”路径。单元测试中的 µVision 进程使用明确标记的模拟实现，与上述真实构建记录分开。

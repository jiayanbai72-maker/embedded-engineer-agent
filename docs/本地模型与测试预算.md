# 本地模型接入与临时测试预算

打开 http://127.0.0.1:8765/，展开顶部“模型设置”。选择模型，粘贴自己的 DeepSeek API Key，勾选启用并保存。已有密钥时留空表示保留。密钥使用 Windows DPAPI 当前用户加密，保存在 runtime/local-model/settings.json；浏览器不保存密钥，不回显，也不会写入项目或交付包。迁移到其他 Windows 账户需重新填写。

保存不调用API。可以点击“测试连接”验证（该请求计入预算），然后创建或打开项目，点击“开始自动推进”。需求和最终方案的关键确认仍由用户进行。禁用模型回到人工分析模式，移除密钥不会删除预算记录。

临时预算固定每天10元，北京时间零点换日，所有项目和两种模型共用。本地 SQLite 记录位于 runtime/local-model/usage.sqlite3，事务预留避免并发请求透支，重启保留。不要删除该目录来清零预算。

统一使用高峰价格保守计账，即使空闲时段也不下调。计算方式为：缓存命中数×命中价 + 其他输入数×未命中价 + 输出数×输出价（均除以一百万）。例如 Flash 10元可支付125万纯输出token，或500万纯未命中输入token；两者不能相加，实际混合用量按费用累计。

已取消本地200KB输入门槛与8192 token输出测试额度，输出使用官方最大393216 token；输入与输出之和仍受服务端上下文限制。每日10元费用保护保留，按余额推导单次可支付的最大输出边界，不另设每日token额度。使用非思考模式；Agent仍通过决策、工具执行、观察和调整完成任务。送给模型的上下文会自动整理：去掉回执重复正文，保留最近三条完整观察、当前需求/约束/验收/用户回答/当前方案及契约，旧轮次和事件明确标为历史摘要；本机原始项目与日志不变。整理过程不调用模型、不产生额外费用。请求前用UTF-8输入字节上界加4096 token消息开销预留，并按最大输出量预留。不再因200KB测试门槛暂停；剩余费用不足以覆盖下一次请求时提前暂停，不会等超过10元后才拦截。真实用量返回后再结算，格式错误的模型回答也计费。缓存统计缺失时按未命中计费。

超时/服务异常/缺少可信usage时，预留金额不退并暂停当天模型调用，避免盲目重试。明确的401等拒绝响应释放预留并暂停本轮，修正密钥后可以手动重试。跨零点请求保守计入两个日期。没有自动重试或后台自动付费调用。

此限制约束通过本地工作台设置入口发起的模型请求，不是DeepSeek账户级封顶，不包含其他软件/其他设备/云端使用同一密钥的费用。价格变动或服务端计费行为变化需核对官方账单并更新PRICES。长期停用此临时保护时集中修改 local_model.py 和服务器入口，不要删除账本来绕过。

## 模型自行读取校验错误

决策上下文提供完整design_plan字段契约。提交前的结构错误保存在run.auto_feedback，含字段路径及attempted_arguments；执行阶段的语义校验错误保存在rejected观察的message/tool_result，含实际校验提示、原提交参数及schema_ref。下一次模型调用自动带上这些信息，无需用户复制错误或填写JSON。旧版仅保存泛化错误的回执无法还原丢失参数，模型会使用完整契约重新构造提案，不宣称已恢复旧内容。

自动推进连续三次决策或执行失败后暂停，防止无效反复调用；成功后清除过期auto_feedback。需求确认、冻结约束、真实观察引用和每日费用限制均不放宽。回归测试使用模拟模型，证明反馈与修正链路；真实DeepSeek能否生成合规方案仍取决于实际调用结果。

### 减少重复费用

外层决策rationale缺失时可复用模型自己在arguments.rationale中提供的依据，不编造工程判断；expected缺失时由程序填写“执行动作并记录实际结果”的中性预期，并在回执metadata_defaults留痕，成功仍由真实回执判定。这类纯记录字段不再触发一次付费重试。旧版因此达到三次暂停的运行允许一次有记录的恢复，费用和步骤不清零，反复失败仍受三次限制。

模型上下文对当前轮次的重复design工具快照只保留指向当前完整轮次的引用、执行时状态和哈希，不重复发送三份研究与检查正文；失败信息、源码读取及原文页结果不裁剪。旧轮次保留状态、原约束和摘要哈希，不重复携带全部缺口。这是确定性整理，不需要额外调用模型。页面显示调用次数及最近一次输入token，方便核对每步开销。

## 可见运行状态

中间任务计划全部取得满足完成条件的回执后，控制器自动归档到plan_history，记录completed_plan及完成回执ID，解除旧计划对下一阶段动作的锁定；无需模型调用，不代表项目整体通过。尚有未完成任务时只向模型提供ready任务的动作，提交仍校验task_id及依赖。已交付的最终计划保留到finish完成，避免提前丢失最终验证流程。

模型请求异常导致用量未知时默认暂停，保留全额预留金额。可在模型设置点击“保留预留费用后继续”：这只将未知费用标为已确认保留，仍全额占用10元日预算，不退款、不清零、不自动重试。用户需手动开始自动推进。后续异常仅记录异常类型、处理阶段和耗时，不记录密钥或原始响应；旧版未记录的异常无法追溯具体原因。

自动推进时每秒读取GET /runs/{id}/progress，显示整理上下文、等待模型响应、校验参数、执行工具以及结束/暂停状态，并显示当前请求等待秒数。模型返回后显示它给出的简短决策依据，不展示内部思维链或伪造生成进度。最近12个状态变化在“查看最近运行过程”中显示；内存进度在重启后清空，正式工具回执仍持久保存。

进度接口可在模型/工具请求未结束时响应；其他工程操作通过同一个互斥锁串行执行，维持原JSON项目存储的一致性。等待提示不是设备成功验收，也不是模型逐token流式输出。模型网络请求超时为90秒，停止自动推进会等待当前步骤结束，不强行重复或中断未知副作用。

达到步骤上限或连续失败后，可点击“保留项目，开始新一轮”，建立新的最多30步运行并继续；原项目、旧回执、费用记录保留，10元日预算不重置。完整power_estimate字段结构已放入action_contracts，包含whole_load_bus、电池basis、典型/保守时长及功率、独立峰值估算。

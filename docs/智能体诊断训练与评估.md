# 智能体诊断训练与评估

这里的“训练”指改进工作流程、案例记忆、工具证据和评估，不改变DeepSeek模型权重，也不保证未来能独立解决全部错误。

## 已接入的诊断能力

- 先读取原测试的期望、实际值和失败位置，逐个区分复合断言的条件。
- 词法函数索引给出当前文件中的函数、调用关系和循环线索；它不是完整C语义分析器。
- 在独立主机重放副本中记录间接回调的文件、行号、调用函数和次数。程序行为与通过判定仍以原测试为准；诊断副本不得用来伪造通过。
- repair_coach按错误类型选择最多两个短案例：回调扇出、阶段计时、声明与实现不一致。案例只提供调查方法，不作为当前项目事实。
- 模型依据当前日志和源码提出简短修复结论，最小修改、保留测试，然后执行真实工具。相同实测失败重复出现时暂停。

## 工具评估与模型评估分开

`tools/evaluate_repair_coach.py`使用改名、不同循环次数的合成C案例：确认工具捕获一次外部动作经辅助函数产生多次回调；确认已知的合成修正版在不改测试时通过。实际执行ARMCC和MSVC，不调用模型。它只证明诊断工具正确，不证明模型学会修复。

下一阶段的模型盲测须把另行保留的故障给模型，记录首次诊断正确率、修复通过率、回归退化、工具次数、模型费用、人工介入和是否修改测试。先通过合成案例，再回放真实失败。未通过的案例保留为失败，不能用人工修订混作模型成功。

当前项目的原始失败、模型修改、人工修改与真实工具报告都保留来源。案例不应把“把脉冲数改成2”当万能答案；必须追踪当前数据流与调用链。


## 首次模型留出评估

已执行一次隔离合成案例盲测：不同函数命名，selected为3及0两种情形，模型自行修改生产源码，原测试保持不变，ARMCC目标编译和MSVC主机断言通过。模型调用1次，保守费用¥0.014662。报告：runtime/draft-validation/repair-model-holdout.json。仅代表一个案例通过，不能推导通用排错成功率，也没有宣称当前机器人修复成功。


小范围修复新增draft_patch：只提交当前文件哈希和唯一匹配的old/new片段，保留全部测试，不重发整份源码。该工具减少代码字符串过长导致的JSON输出失败，不改变模型生成的工程内容。真实项目的教练辅助与模型独立盲测分别记账、分别报告，不将人工诊断提示混作完全独立成功。


诊断重放增加branch_trace：仅对简单局部标量比较记录实测左右值及比较结果，保留短路与分支顺序，跳过volatile变量。帮助区分条件未到、条件被遮蔽、超时路径错误。当前机器人本轮原超时断电测试已通过，停在时钟回绕后的回中时序断言；不宣称完整测试通过。


已加入回归检查点：同一测试版本下，实际观测通过的断言集合若在失败候选中丢失，则保留候选和报告并恢复源码检查点。诊断不可用时不凭缺失数据推断回归。训练新增独立计时案例：正常边界、32位时钟回绕和总超时，模型单次自行修复通过，原测试未修改，费用¥0.017228。它仍不代表当前机器人已通过。


回归保护真实工具评估见runtime/draft-validation/regression-guard-proof.json：同一测试中已通过的第一条断言在候选中丢失，候选被保留且检查点恢复。当前机器人已恢复到时钟回绕回中断言失败的基线（观测17个不同断言位置通过）；这不是完整测试通过，不能按17条直接推算总完成率。

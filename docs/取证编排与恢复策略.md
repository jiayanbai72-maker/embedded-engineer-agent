# 取证编排与恢复策略

## 谁完成了什么

模型负责提出工程方案、解读原文和提交参数或关系；工具负责读取资料、核对引用和保存证据。本次开发由 Codex 修改框架和校验器，不能把此前需要人工修框架才走通的过程说成 Agent 已完全独立完成。这是编排改进，不是训练模型权重。

## 原来的问题

- 研究任务混入固件修复等指令，模型需要猜当前角色。
- 引用失效、语义证据不足、格式错误和费用异常缺少不同的恢复路径。
- 重复请求被直接停止，已有回执没有充分用于后续修正。
- 普通关系校验错误地附加引脚 AF 与封装要求，导致正确的普通关系也被拒绝。

## 当前流程

任务契约与固定目标 → 读取来源 → 模型提出提交 → 工具校验 → 保存或分类恢复 → 汇总结束。

| 失败类别 | 后续处理 |
| --- | --- |
| 引用失效 | 程序最多自动重读同一来源一次，再由模型修正引用 |
| 表格布局不足 | 重读同一页的布局，保留行列关系 |
| 语义证据不足 | 模型缩小或修正主张，不能靠重复读取获得通过 |
| 输出格式或参数错误 | 按契约修正，不启动无关搜索 |
| 重复读取 | 复用真实成功回执，连续重复后收束 |
| 来源完整性或费用异常 | 暂停，不自动绕过 |

恢复同样消耗正常工具步骤，不重置每日费用。成功进度按实际保存的唯一证据记录计算，不按模型文字计算。目标契约限制模型用其他容易登记的事实替代原任务。最后一步优先收束；未补齐的证据保持缺口。

实现入口为 `src/embedded_agent/research_orchestration.py`，并接入控制器、执行器和研究上下文。一般关系只检查自身语义；AF 与封装条件仅用于对应关系。

## 验证与边界

2026-10-19 离线检查：196 项测试通过，2 项跳过。

另用已配置的 DeepSeek 进行两个隔离的合成资料测试：普通信号关系、数值电压参数。预先注入失效引用后，两例均自动读取同一来源一次，由模型重新提交，经真实校验保存记录并结束；每例共 4 个工具步骤。修正后的复测记账约 ¥0.0601。首次测试还发现普通关系被错误附加 AF/封装要求，修正后才复测通过。

真实调用报告：`runtime/orchestration/transfer-live.json`。合成资料不是实际硬件规格，也没有写入原工程资料库。

这些结果只证明两类新资料的引用恢复路径可用，不能证明所有未知错误均可独立解决。仍须通过更多不同来源、表格布局与失败类型评估。硬件、电气、实际续航与采购预算验收保持原状态，未因本次恢复测试而通过。

## 后续补强（2026-10-19）

- 一般取证结束保存 `evidence_completion`：只有当前有效登记记录逐字段满足固定目标时才是 `verified`，否则为 `ended_with_gaps`。无固定目标不声称目标验证通过。前后端均展示两种不同结果。
- 读取新的唯一来源页或登记新的唯一记录后，清零连续重复计数；重复同一页或同一记录不算进展。保留正常步骤与费用上限。
- 引用失效、布局不足、来源哈希变化由来源校验处抛出结构化错误，包含错误类别和适用字段；语义拒绝返回明确类别。旧回执仍保留文字分类兼容。
- 增加有效目标匹配、误报完成、重启复用回执、来源版本变化、相邻页面、空回执、布局失败与联网失败的离线回归。完整回归 201 项通过（2 项跳过），其后新增边界与相关测试共 18 项通过；界面语法检查通过。本次未调用付费模型。

不可读的扫描页仍需合适的 OCR/图像理解能力，本次只验证安全保留缺口，不宣称已解决任意扫描件识别。联网失败也不等于资料不存在。

## 2026-10-20 检查修复

一般只读取证现在可以在工程未交付阶段结束，结束记录只表示本轮取证结果，不改变工程阶段、版本或交付验收。保留最后一个工具步骤用于结束，避免读完资料却无法保存结果。

来源完整性错误在执行器中直接阻塞后续模型与工具调用，且优先于最后一步收束，不再只靠提示词约束。恢复可信来源后应新建取证运行，原错误及费用记录保留。

取证目标不能混合数值与关系字段，即使仅混入一个字段也会在创建时拒绝。新增回归覆盖上述边界。

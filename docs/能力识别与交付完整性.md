# 能力识别与交付完整性

开发板不是当前离线开发流程的前置条件。纸盒机器人只是案例；本模块不包含固定芯片、特定机器人动作或板卡参数。

工作台新增“能力与交付检查”页，可查看当前项目需求、设计、工具验证记录、估算与待补项。读取不会修改项目或自动确认方案。重新打开此页会读取最新报告。

## 数据接口

- `GET /capabilities`：本地检索索引、约束计算、主机构建、ARMCC 文件配置、模型接入及硬件执行能力状态。编译器文件存在只代表已配置，实际执行成功须看构建回执；不扫描串口，不假装已检测开发板。
- `GET /projects/{id}/readiness`：根据保存的项目材料计算当前离线交付范围的缺口。主机原型、目标文件编译、演练固件构建分别判断，只将当前决策 actions 要求的构建与测试纳入范围阻塞项。
- 运行上下文新增 `capability_status` 和 `readiness`，供后续模型根据现有能力决定下一步，而不是假定所有工具可用。

新生成的交付包包含 `delivery-assessment.json`，冻结导出前项目版本的检查结果。它说明已完成范围及未执行环节，不认证全部硬件约束，不认证参数来源仍有效，也不代替正式验收。历史交付包维持原内容及哈希；不会因机器配置变化重新生成这份报告。

## 当前完成边界

已有需求与候选分析契约、任务依赖、检索和页码引用、参数审核、约束检查、功耗估算、工具构建与测试、持久化执行及文档打包。分析判断仍由外部分析者提供；未连接自动决策模型。电商报价暂缓，整机功耗属于估算，烧录和实机验证适配器尚未实现。

后续接入模型时，应让模型消费这些上下文并提交受限决策，沿用控制器回执和权限边界。拿到开发板后再实现板卡配置、烧录、串口采集和验收证据接口；不得通过修改一个状态字段将硬件标记为通过。

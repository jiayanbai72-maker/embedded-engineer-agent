# 自动决策与运行入口

使用者不应逐步填写计划、工具动作和分析 JSON。自动运行器将当前需求、允许动作、实际回执、任务进度、能力缺口交给决策者，接收下一步动作或计划并执行，再把结果交回决策者。界面中的逐步入口保留用于调试。

## 当前使用

在“项目操作”页点击“开始自动推进”；无运行时自动创建。浏览器每次只请求一个步骤，收到结果后才继续；关闭页面或点停止即不再请求新步骤。当前步骤不会强制中断。它不是后台无人值守任务，刷新后需重新点击继续，已有控制器负责恢复持久化状态。

当前按用户要求不接真实模型。点击开始会明确显示“自动决策模型未接入”，不会生成预设答案或执行模拟决策。

将来实际接入时，本机须设置既有 `EMBEDDED_AGENT_ENDPOINT`（完整 HTTPS Chat Completions 接口）、`EMBEDDED_AGENT_MODEL`、`EMBEDDED_AGENT_API_KEY`，另设 `EMBEDDED_AGENT_AUTONOMY=1` 明确启用，重启服务。仅有原模型配置不会自动发请求。点击自动推进才发送当前项目上下文与执行结果给配置的服务；密钥只从环境读取，不填入项目与决策。当前版本真实服务兼容性尚未联调。

## 判断与执行契约

`POST /runs/{id}/auto {}` 返回 `status`、`message`、`context`。continue 表示允许浏览器请求下一步；paused 或 model_not_connected 停止循环。该接口不会自行选择另一个项目。

决策者输出三类 JSON：

- decision：action、arguments、rationale（简明依据）、expected，可选 task_id。控制器设置唯一编号、项目版本与来源，重新检查权限、任务依赖和阶段。
- plan：plan 对象，沿用通用任务计划契约；允许模型自己拆解任务，而不是要求使用者编辑。
- pause：reason，清楚说明必须暂停的具体原因。

沿用每轮步骤、修复次数预算；另将模型判断次数限制为步骤预算的两倍，避免只更新计划却永不执行。连续三次无效决策或失败结果后停止。测试失败的实际回执仍保留，模型可据此修复。缺少决定性信息可 ask，用户确认与最终选型仍不允许模型代行。

## 仍需完成

该模块完成的是自动循环和接入边界，不是已经上线的自主智能。当前提示提供了动作范围及计划契约，但各工程动作的完整机器可读输入 schema、模型实测评估、长上下文裁剪、首次需求的一键分析及面向用户的对话式确认仍需补齐。模型输出不合契约时会暂停，不能声称端到端自主交付已完成。无开发板不阻断这些工作；真实烧录与实机验证留待硬件接入。

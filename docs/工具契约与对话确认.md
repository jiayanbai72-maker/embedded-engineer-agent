# 工具契约与对话确认

当前运行上下文新增 `action_contracts`，按允许动作提供 arguments_schema。覆盖所有控制器动作：需求分析、资料检索、原文读取、审核参数读取、源码提交、主机构建与测试、MCU编译、演练固件构建、候选研究与约束计算、功耗估算、提问和导出。

schema 在本地先检查字段、类型、枚举和基本边界；随后仍由服务完成阶段、引用、来源、量纲、指纹等语义校验。不是所有复杂模型都已拆成完整嵌套 schema：design_plan、power_estimate 的详细语义来自 engineering_guides，selection_check 的 inputs 和参数绑定仍由专属验证器判断。没有将不完整结构宣称为完整 JSON Schema 校验器。

`analysis_references` 提供实际可引用的通用知识卡片。它们用于需求分析方法，不能证明某款器件的参数；器件证据仍需检索、原文与审核记录。

Agent 提问后，项目操作页出现“需要你参与的事项”。用户自然语言回答，点击“发送回答并继续”，系统写入运行上下文并恢复自动推进。无需运行编号或 JSON。

`POST /runs/{id}/reply`：`{revision,message}`，只接受正在 waiting_input 的当前版本运行。项目被其他操作修改时拒绝过期回答。回答记录持久化，最多30条，每条4000字符。此接口不修改已确认需求、不接受方案、不执行工具。涉及已确认工程约束的变更仍须走补充需求与重新确认流程。

需求草稿没有阻塞问题时显示“确认需求并继续”；自动运行在这里等待用户核对，不能自行确认。下一步方案选择也由用户页面操作。其余工具动作与参数由 Agent 内部处理，详细分析者入口仅用于调试。

自动运行遇到结构错误会保存 auto_feedback 供模型修正，最多连续三次；正常读取、构建、测试结果仍保存在回执中。外部项目变更后自动同步上下文并归档旧计划，不复用过期任务结论。

当前未接真实模型，测试使用明确标记的契约测试 provider，不代表已验证真实模型自主交付。当前阶段只在出现开发板相关任务时保留硬件待验证项，不要求用户先有开发板。

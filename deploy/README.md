# 在线工作台部署（自备API）

这是现有Python工程引擎的在线入口，不是把本机端口直接暴露到公网。未发布到公网，需部署者提供服务器与域名。Sites的Workers托管无法直接运行本Python后端，故使用容器部署。

## 支持范围

- 沿用左侧工程区、右侧聊天，使用者在“修改模型/API”中填写自己的DeepSeek官方API。
- 分析、需求确认、方案比较、源码/文档生成和未验证草案下载。
- 每个浏览器会话使用独立工程目录、对话、预算库和模型实例。密钥只在当前服务进程会话内存中，不写配置文件、日志或镜像。
- 会话有效8小时，最多8个并发访客会话；退出后清理访客目录与密钥。服务重启、会话到期都会失去匿名会话，请提前下载项目。
- 当前在线入口为邀请试用，需要部署者提供访问口令（浏览器弹窗用户名可任意填写）。没有账户注册或跨设备项目恢复，不应宣传成带长期云存储的正式多租户服务。
- 每日10元保护只覆盖当前访客会话，不是服务商账户的全局限额。服务商后台实际计费为准。

## 不提供的在线执行能力

尚未配置隔离执行器，不在共享服务器执行使用者或模型提交的Python/C代码，不编译、不运行测试、不开Keil、不访问服务器串口。浏览器无法直接操控使用者电脑上的Keil或开发板。生成的源码可以导出，在本机继续编译与烧录。

当前在线部署不开放联网资料抓取与自定义API地址：前者需另外配置受控执行器，后者需部署者审核服务商地址，防止访问内网。不能伪称工具已经执行或硬件验证通过。

## 上线准备

1. 准备支持Docker Compose的Linux服务器与域名，将域名解析到服务器，开放80/443。
2. 复制本项目的干净源码；**不要上传runtime、私有项目、聊天、密钥文件、厂商下载资料或Keil安装目录**。Docker构建只复制源码和自编通用知识卡。
3. 将`deploy/.env.example`复制为`deploy/.env`，填写域名和随机访问口令（至少16字符，建议32字节随机值）。这个口令不是大模型API Key，勿提交版本库。
4. 在`deploy`目录运行：

```text
docker compose --env-file .env -f compose.yml up -d --build
```

5. 打开`https://你的域名/`。HTTPS由Caddy处理。首次填写访问口令后，每位使用者自行填写API；保存配置不发起付费请求。

后台8080不映射公网，只由HTTPS代理访问。PUBLIC_URL必须与实际来源完全相同，不能以通配符放宽Host/Origin检查。容器使用非root用户、只读根文件系统、限制内存/进程及临时空间，仍不等于代码执行沙箱，所以在线执行功能保持关闭。公开发布前还需部署环境安全审查、监控、资源配额及账户设计。

## 本机在线模式预览

设置`PUBLIC_URL=http://127.0.0.1:8788`和至少16字符的`ONLINE_ACCESS_CODE`环境变量，使用本项目Python环境运行：

```text
python -m embedded_agent.online_gateway --host 127.0.0.1 --port 8788
```

不得把个人API写入部署环境变量。8786仍为原来的本机工作台，其DPAPI配置不进入在线会话。退出本机API只移除本机保存的密钥，不会替用户撤销服务商后台的密钥。
